AI Agent 생태계는 새로운 공급망 위험을 만드는가

Model·MCP·Tool·Plugin·API가 연결될수록 넓어지는 Trust Boundary

2026년 11월 4일 약 9분#14 / 75

전통적인 소프트웨어 공급망은 라이브러리, 패키지, 빌드도구, 배포아티팩트의 신뢰성을 관리해왔다. Agentic AI는 여기에 모델, Prompt, RAG Source, MCP Server, Tool, Plugin, 외부 API와 Agent 간 위임관계를 추가한다. 구성요소 하나가 바뀌면 Agent가 할 수 있는 행동 자체가 달라질 수 있다.

RESEARCH QUESTION
AI Agent의 공급망 위험을 소프트웨어 구성요소의 무결성뿐 아니라 ‘누가 어떤 Tool에 어떤 권한으로 연결되는가’까지 확장해 관리해야 하는가?

1. Agent 공급망은 코드와 권한을 동시에 전달한다

OWASP GenAI 자료는 Supply Chain과 Excessive Agency를 주요 위험으로 다룬다. Agent는 외부 Tool을 호출하고 결과를 다음 행동의 입력으로 사용하기 때문에 취약한 Plugin이나 오염된 데이터가 실행결정에 직접 영향을 줄 수 있다.

전통적 Dependency Risk에 Runtime Authority가 결합된다는 점이 Agent 생태계의 특징이다.

2. 새로운 자산목록이 필요하다

SBOM이 소프트웨어 구성요소를 가시화하듯 Agent 시스템도 연결된 모델·데이터·도구·권한을 추적할 수 있어야 한다.

02

MCP·Plugin·API와 허용 Action

Service Account·Token·Scope·위임관계

3. Trust Boundary는 연결마다 생긴다

외부 Model API에서 내부 RAG로, Agent에서 MCP Server로, MCP에서 SaaS API로 이동할 때마다 인증, 데이터노출, 출력검증, 권한경계가 달라진다. 공급망 검토는 벤더 보안평가만으로 충분하지 않고 각 연결의 데이터와 행동권한을 확인해야 한다.

특히 Tool 설명이나 외부 콘텐츠가 Agent의 판단에 영향을 주는 환경에서는 입력 신뢰도와 Tool Allowlist, 결과 검증이 중요하다.

4. 소프트웨어 공급망 통제를 Agent에 확장한다

NIST SSDF와 C-SCRM의 원칙은 Agent 환경에서도 유효하다. 출처가 확인된 구성요소, 변경 추적, 취약점·벤더 관리, 최소권한, 운영 모니터링을 Model·Prompt·Tool까지 확대하면 된다.

여기에 Agent 고유의 위임체인과 실행로그를 더하면 ‘어떤 공급망 요소가 어떤 행동권한에 연결되어 있었는가’를 설명할 수 있다.

AGENT BOM
Software BOM + Model/Data/Tool Inventory + Authority Graph

Agent 시스템의 가시성은 코드목록만으로 완성되지 않는다. 실행 시점에 연결되는 Tool과 Credential, 데이터 경로를 함께 그린 Authority Graph가 있어야 영향범위를 판단할 수 있다.

마치며

Agentic AI는 공급망 위험을 없애지 않고 오히려 코드·데이터·모델·권한을 하나의 실행체계로 결합한다. 따라서 공급망 보안도 ‘무엇이 설치되어 있는가’에서 ‘무엇이 누구의 권한으로 무엇을 할 수 있는가’까지 확장될 필요가 있다.

Agent 시대의 SBOM에는 구성요소뿐 아니라 행동할 수 있는 권한의 경로도 보여야 한다.
