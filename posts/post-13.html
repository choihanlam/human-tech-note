AI 시대의 경쟁우위는 모델인가, 조직의 데이터와 지식인가

범용 Foundation Model 시대에 지속가능한 차이를 만드는 자원은 무엇인지 Resource-Based View로 다시 보기

2026년 11월 4일 약 13분#13 / 75

AI 모델의 성능 차이는 빠르게 줄어들고 있다. 동일한 Foundation Model API를 경쟁사도 사용할 수 있고, 새로운 모델이 등장하면 기존의 기술우위가 짧은 시간 안에 바뀔 수 있다. 그렇다면 ‘최신 모델을 먼저 도입했다’는 사실만으로 지속적인 경쟁우위를 설명할 수 있을까?

이 질문은 기술경영에서 익숙한 Resource-Based View와 연결된다. 경쟁우위가 외부 시장에서 누구나 구매할 수 있는 자원보다 기업 고유의 데이터, 프로세스, 조직지식, 학습능력에서 만들어진다면 AI 시대에도 중요한 것은 모델 자체보다 모델이 읽고 행동하는 기업의 맥락일 수 있다.

이 글은 모델과 데이터 중 하나를 선택하려는 것이 아니다. 범용기술이 확산될수록 어떤 자원이 차별화를 남기는지를 살펴본다.

이 글의 중심 질문
누구나 비슷한 Foundation Model을 사용할 수 있는 환경에서 지속가능한 경쟁우위의 원천은 모델 자체보다 기업 고유의 데이터·Tacit Knowledge·업무 프로세스·학습속도로 이동하는가?

1. RBV의 질문을 AI에 적용하면 ‘희소한 모델인가?’부터 의심하게 된다

Barney의 Resource-Based View는 가치 있고(Valuable), 희소하며(Rare), 모방이 어렵고(Inimitable), 조직화된(Organized) 자원이 지속적 경쟁우위를 만들 수 있다고 본다. 널리 판매되는 Foundation Model은 가치가 높아도 희소성과 모방난이도는 낮아질 수 있다.

반면 오랜 고객관계에서 쌓인 데이터, 운영현장에서 축적된 예외처리 규칙, 조직 간 협업방식, 전문가가 암묵적으로 알고 있는 판단기준은 경쟁사가 단기간에 구매하기 어렵다.

따라서 AI 전략의 질문은 ‘어떤 모델을 쓰는가’에서 ‘우리 조직만 가진 어떤 Context를 모델과 연결하는가’로 이동한다.

2. 데이터의 양보다 ‘의미와 권한이 정리된 데이터’가 중요하다

기업이 많은 데이터를 갖고 있어도 최신성, 출처, 품질, Access Control이 정리되지 않으면 AI가 신뢰할 수 있게 사용하기 어렵다. RAG를 붙이는 순간 데이터의 양이 경쟁력이 되는 것이 아니라 검색 가능한 구조와 메타데이터, 권한필터가 경쟁력에 영향을 준다.

특히 내부지식은 Document만으로 표현되지 않는다. 어떤 예외를 허용하는지, 어떤 고객상황에서 어떤 판단을 내리는지, 장애가 나면 어떤 순서로 대응하는지 같은 Tacit Knowledge가 실제 업무의 품질을 좌우한다.

AI가 이 지식을 활용하려면 사람이 머릿속에 가진 기준을 사례, Rule, Label, Feedback으로 구조화해야 한다.

자원단순 보유 상태AI 경쟁력으로 전환된 상태
데이터대량 저장출처·품질·권한·의미가 연결됨
문서파일서버/협업도구에 존재검색·버전·Owner·접근권한이 구조화됨
전문가 지식개인의 경험Case·Decision Rule·Feedback으로 조직지식화
프로세스부서별 관행입력·판단·예외·KPI가 명시된 Workflow

3. 경쟁우위는 ‘Model Selection’보다 ‘Learning Loop’에서 생길 수 있다

모델은 계속 바뀐다. 이 환경에서 한 번의 좋은 선택보다 중요한 것은 새로운 모델을 얼마나 빨리 시험하고, 조직 데이터와 연결하고, 오류를 측정하고, 정책을 갱신하는가이다.

Dynamic Capability 관점에서는 시장과 기술변화를 Sense하고, 기회를 Seize하며, 조직자원을 Transform하는 능력이 중요하다. AI에 대입하면 모델 벤치마크를 보는 능력보다 실제 업무에 빠르게 실험하고 Scale하는 운영역량이 더 지속적일 수 있다.

같은 모델을 사용해도 Feedback Loop가 빠른 기업은 Prompt, Data, Tool, Process를 지속적으로 개선하면서 격차를 벌릴 수 있다.

4. AI Native Enterprise의 자산은 ‘모델’보다 연결구조일 수 있다

Agent가 기업시스템에서 실제 행동을 하려면 Identity, Tool, API, Data, Workflow, Policy가 연결되어야 한다. 이 연결구조는 단순 API Integration이 아니라 조직의 업무규칙과 책임구조를 코드와 정책으로 표현한 것이다.

따라서 장기적으로 기업이 쌓는 자산은 Prompt 모음보다 Process Ontology, Knowledge Graph, Access Policy, Evaluation Dataset, Decision Log에 가까울 수 있다.

이 자산들은 특정 모델을 바꿔도 남는다. 오히려 Model Swap이 가능하도록 조직의 Context를 분리해 관리하는 것이 전략적 유연성을 높인다.

01

Evaluation Dataset

우리 업무에서 좋은 답·나쁜 답을 구분하는 기준

02

데이터·문서·개념의 연결구조

04

Governance Assets

Policy, Risk Register, Audit Trail, Approval Rule

5. 모델을 소유하지 않아도 경쟁우위를 만들 수 있다

모델을 직접 개발하는 기업과 API를 사용하는 기업의 전략은 다르다. 자체 모델이 핵심자산인 산업도 있지만 대부분의 기업에서는 모델 자체보다 업무와 고객가치에 어떻게 연결하는지가 더 중요할 수 있다.

이는 Cloud 시대와도 유사하다. 서버를 직접 제조하지 않아도 Cloud Architecture와 운영역량에서 경쟁력을 만들 수 있었다. AI도 Foundation Model을 외부에서 조달하면서 기업 고유의 Process·Data·Governance를 차별화할 수 있다.

결국 Make vs Buy보다 ‘무엇을 외부에 맡겨도 되고 무엇은 내부 Capability로 남겨야 하는가’를 정하는 것이 전략의 핵심이다.

RESEARCHER'S NOTE

기술경영을 공부하면서 AI를 바라보는 관점이 ‘기술이 얼마나 발전했는가’에서 ‘기업이 그 기술을 어떤 자원과 결합해 가치를 포착하는가’로 확장됐다. 이 관점은 모델 성능 경쟁이 빠르게 평준화되는 지금 더 중요해졌다고 생각한다.

특히 정보보호와 IT 운영 경험을 돌아보면 조직만의 강점은 솔루션 이름보다 운영사례, 예외처리 기준, 협업구조와 같은 Tacit Knowledge에 있었다. AI가 이런 지식을 구조화하고 재사용할 수 있다면 그것 자체가 기업의 지식자산이 될 수 있다.

반론과 한계

LIMITATION

RBV는 기업 내부자원의 중요성을 설명하는 강력한 틀이지만 산업구조·네트워크 효과·규제·Platform Power 같은 외부요인을 충분히 설명하지 못할 수 있다. AI 경쟁우위는 내부 Capability와 외부 생태계 위치를 함께 봐야 한다.
